# 公网演示与本地真实 API 体验边界设计

## 目标

公网 WebUI 清晰展示项目的三种体验，但只允许匿名用户运行确定性的安全演示。需要真实 API Key 或服务器凭据的体验仅在下载完整项目并以本地可信模式运行后开放。公网部署不接收、不保存、不使用任何用户 API Key，也不消耗项目维护者的服务器凭据。

## 用户可见行为

### 公网安全模式（`HARNESS_MODE=public`）

- 页面展示三张体验卡片：安全演示、使用自己的 API Key、本地服务器凭据。
- 安全演示可选择并运行。
- 另外两张卡片保持可见但禁用，并分别说明：
  - 使用自己的 API Key：公网演示不接收 API Key；下载完整项目并在 `localhost` 或 `127.0.0.1` 上运行后可用。
  - 本地服务器凭据：仅本地可信模式可用，由本机用户配置、查看状态、更新和清除。
- 不显示 API Key 输入框，不向任何请求写入 API Key。
- 配置页保留，但只展示公网/本地能力边界和本地启动提示，不开放凭据管理接口。
- 对话与浏览器本地历史页面继续可用。

### 本地可信模式（`HARNESS_MODE=local`）

- 三种体验均按服务端签发的能力正常可用。
- 使用自己的 API Key 允许在 loopback HTTP 下运行，Key 仅用于当前请求。
- 本地服务器凭据继续使用现有本地配置和安全存储流程。
- 完整工具集和现有历史/配置行为不变。

## 安全边界

服务端是能力真相来源。`public` 会话的 `allowedExperiences` 只包含 `demo`，并令 `allowByok=false`、`allowServerCredentials=false`。路由层继续校验签发能力，因此即使客户端被篡改，`byok` 或 `server` 请求也会被拒绝。

客户端不会通过隐藏元素表达权限。它从固定的三种体验目录生成卡片，再以服务端能力决定是否可操作。禁用卡片仅用于解释本地能力，不赋予权限。

## 组件变化

- 服务端运行策略：公开模式只签发 `demo` 能力；本地模式保持现状。
- `ChatPanel`：从固定体验目录渲染三张卡片；增加每种体验的可用范围说明和禁用原因；公开模式不渲染 BYOK 输入框。
- `ConfigPage`：公开模式说明完整项目的本地启动方式与凭据边界，不调用凭据写接口。
- `README.md`：增加“公网演示与本地完整版本”章节和对照表，给出 Windows PowerShell 本地启动命令，并说明公网 URL 只用于安全演示。

## 数据流

1. 浏览器申请会话。
2. 服务端根据 `HARNESS_MODE` 返回模式与能力。
3. 客户端始终展示三种体验，但只允许选择 `allowedExperiences` 中的项。
4. 公网提交只能发送 `mode=demo`，服务端再次验证能力。
5. 本地运行时，用户可按服务端能力选择 `demo`、`byok` 或 `server`。

## 错误处理

- 客户端若尝试提交未授权体验，显示稳定的“不受允许”提示并清理临时 Key。
- 服务端对伪造的公网 `byok`/`server` 请求保持拒绝，不调用真实 LLM 或凭据存储。
- 本地凭据不存在时沿用现有配置引导，不将密钥明文返回到页面状态接口。

## 测试策略

- 服务端策略测试：公开会话仅签发 `demo`；本地会话仍签发三种体验。
- 路由测试：伪造的公开 `byok` 和 `server` 请求均被拒绝，适配器与凭据存储不被调用。
- 前端测试：公网显示三张卡片，后两张禁用并包含本地运行说明；无 API Key 输入框。
- 前端回归：本地模式三种体验仍可选择，BYOK 输入和服务器凭据路径不退化。
- 文档检查：README 的模式表、启动命令和实现一致，不宣称公网支持 BYOK。

## 非目标

- 不配置域名、HTTPS、ngrok 或其他隧道。
- 不向公网开放维护者的服务器 API Key。
- 不增加下载按钮或自动下载安装程序。
- 不发布新的容器镜像或包管理器产物。
- 不改变 Mock LLM 安全演示的确定性行为。

## 验收标准

1. 公网页面同时展示三种体验，只有安全演示可操作。
2. 公网请求无法启动 `byok` 或 `server` 模式。
3. 本地模式仍可使用用户自己的 API Key 和本地服务器凭据。
4. 网页与 README 对公网和本地能力的说明一致、无歧义。
5. 聚焦测试、相关回归测试、构建和差异检查通过。
