# 过程文档全生命周期恢复设计

## 问题

当前 `SPEC_PROCESS.md` 和 `AGENT_LOG.md` 只保留了 2026-08-12 至 2026-08-13 的最终加固过程，遗漏了 Git 历史中可确认的 2026-07-25 至 2026-08-11 关键节点。这与 AI4SE 对规约形成过程和实现过程证据的要求不一致。

## 证据原则

恢复内容按可信度分为三类：

1. Git commit、仓库文件和保存的设计/计划可以交叉确认的事实，直接陈述并附 commit 或路径。
2. 历史版本日志保存但缺少原始会话的内容，标记为“历史日志记录”，不得改写成当前重新验证的事实。
3. 无法确认的原始 prompt 全文、subagent 名称、精确耗时和外部部署结果不补造；存在方法偏差时如实记录。

## 文档边界

### `SPEC_PROCESS.md`

围绕“规约如何形成和修正”组织，而不是罗列全部代码提交：

- 2026-07-25 初始 brainstorming、SPEC 和 PLAN；
- 至少三轮关键设计迭代及采纳/推翻决策；
- 2026-08-03 补做的陌生智能体冷启动及其暴露的缺陷；
- 2026-08-08、08-09、08-12、08-13 的安全、部署、凭据和本地优先设计演进；
- Superpowers 方法效果、局限和全部已知偏差。

### `AGENT_LOG.md`

按时间顺序覆盖 2026-07-25 至 2026-08-13 的关键实现节点。每项尽可能包含日期/task、技能或工作方式、context、commit、人工干预和教训。早期 62 个任务按阶段归组，不为每个微小提交重复一项。

## 一致性约束

- 历史方案必须标注“已被替代”，不能与当前 OS keyring、本地完整 WebUI、静态线上演示和持久化输出方案并列为现状。
- 测试数量绑定到对应日期或任务，不冒充永久总数。
- 冷启动验证明确标注为实现后补做，不能改写成课程要求的“实现前验证”。
- 初期直接在 `master` 开发、后来创建回溯 PR，以及最终加固本地合并未建 PR，均作为方法偏差保留。
- 不修改 `REFLECTION.md`，不触碰用户未跟踪文件。

## 验证

1. 检查两份文档均覆盖 7 月 25 日、8 月 3 日、8 月 7–9 日、8 月 12 日和 8 月 13 日。
2. 对照 AI4SE §4.4、§4.5、§4.6、§4.7、§4.9 逐项检查。
3. 运行文档 consistency checker 和 docs tests。
4. 检查 Git diff、敏感信息和未跟踪文件边界。
